## 📋 前置条件

- 一位愿意参与的受访者（现有用户、潜在用户，或目标人群中的任何人）
- 一个视频通话工具：Zoom、Google Meet，甚至电话都可以
- 录音方式——第 1 步会详细介绍
- 一间安静的房间，预留 45 分钟
- 通话期间在另一个标签页打开本指南

## 第 1 步：配置录音并向受访者说明（0–10 分钟）

你需要把一切都记录下来，这样才能停止疯狂记笔记，真正专注于倾听。差劲的笔记长这样："提到了 dashboard 什么——回头再查。"好的笔记是事后可以复盘的完整对话记录。

**方案 A — Zoom（最简单）**

```
1. 开启 Zoom 会议
2. 点击「录制」→「录制到本地」
3. 通话结束后，Zoom 自动保存 .mp4 和 .m4a 音频文件
```

**方案 B — Google Meet + Tactiq（免费 Chrome 扩展）**

```
1. 从 Chrome 应用商店安装 Tactiq
2. 开启 Meet 通话
3. 点击 Tactiq 图标 → 开始转录
4. 实时字幕自动保存到你的 Google Doc
```

**方案 C — 不用任何工具，只用手机**

```
1. 把手机屏幕朝下放在桌上
2. 打开「语音备忘录」（iOS）或「录音机」（Android）
3. 拨号前先点击录音
```

录音准备好后，用下面这段话开场——逐字朗读：

```
"感谢你抽出时间。我想了解你的真实体验，
不是来推销任何东西的。没有标准答案——
说实话，你越直接，对我越有帮助。
我可以录音吗？这样我就不用边聊边记了，
录音只在内部使用。"
```

大多数人会同意。如果对方拒绝，完全没问题——切换为要点笔记，继续进行。

<Checkpoint>
继续之前确认：录音指示灯是否显示红色/激活状态？你能看清受访者的脸、听清他们的声音吗？
<Answer>是的——录音指示灯已激活，音频清晰，受访者已同意继续。如果对方拒绝录音，你应该已打开一份空白笔记文档。</Answer>
</Checkpoint>

## 第 2 步：进行开场与背景问题（10–25 分钟）

这个阶段的目标是搞清楚这个人究竟是谁、他们的日常是什么样的——在问任何产品问题之前。

**糟糕的开场问题：** "你觉得我们的产品怎么样？"
**好的开场问题：** "跟我讲讲上一次你尝试解决〔你的产品针对的问题〕是怎么回事。"

好的问法会引出一个故事。故事包含真实细节。细节才会变成洞察。

以下是问题 1–6，把它们粘贴到文档里，通话时保持可见：

```markdown
## 开场与背景（问题 1–6）

Q1："能简单介绍一下你自己，以及你日常主要做什么吗？"
    → 让对方说 2 分钟，不要打断。

Q2："〔这个问题〕是什么时候开始成为你必须面对的事情的？"
    → 你要的是起源故事，不是摘要。

Q3："跟我讲讲上一次你处理〔这个问题〕的经过，
     一步一步来，发生了什么？"
    → 神奇的问题。如果他们跳过某些步骤，让他们慢下来。

Q4："在那之前你在做什么？是什么触发了这件事？"
    → 问题发生前的上下文，对定位来说是黄金。

Q5："还有其他人参与吗？有人帮你吗？"
    → 挖出隐藏的利益相关者和影响者。

Q6："之前你试过什么方法？是什么让你停下来不用了？"
    → 竞品和替代方案情报，这题绝对不能跳过。
```

**这个阶段最重要的规则：** 每次对方回答完，沉默整整 3 秒再开口。沉默对你来说很尴尬，但对对方来说，这意味着你在认真思考。他们会用本来打算省略的最真实的话来填补这段沉默。

## 第 3 步：深挖核心痛点问题（25–40 分钟）

大多数访谈者在这个阶段变得客气，把整个访谈浪费掉。你不会这样。

你要寻找的是情绪强度——那些对方声音变化、身体前倾，或说出"说实话"、"你听着"的时刻。这些是你放慢节奏、深入挖掘的信号。

```markdown
## 核心痛点问题（问题 7–12）

Q7:  "那次经历里最让你抓狂的是什么？"
     → 如果对方说"还好"，就问："怎样能让它好十倍？"
       "还好"永远不是真的还好。

Q8:  "当时你心里是什么感受？"
     → 要情绪，不要功能描述。这句话最后会出现在你的汇报里。

Q9:  "如果这个问题一直解决不了，代价是什么？
     时间？金钱？压力？"
     → 把痛量化。每月 200 美元或每周 3 小时是标题。
       "有点烦"不是。

Q10: "你有没有跟别人说起过这个问题？你怎么跟他们描述的？"
     → 挖出自然语言。把他们的原话用到你的文案里。

Q11: "你自己试过什么办法解决它？"
     → 变通方法 = 未被满足的需求。用电子表格凑合 =
       产品机会。

Q12: "这些方案哪里没达到你的期望？"
     → 现有方案与真实需求之间的差距。
```

当对方只给你一句话的答案时，用这个万能追问：

```
"能多说一点吗？"
```

四个字，每个问题都好用。不要滥用——但每次访谈至少用三次。

<Checkpoint>
38 分钟处确认：你是否已经记录了至少一句带情绪的直接引用，以及一个具体数字（时间、金钱或频率）？
<Answer>是的——你有一句体现挫败感或解脱感的引用，以及一个具体数字，比如每周 2 小时或浪费了 50 美元。如果没有，现在就用 Q9，然后再继续。</Answer>
</Checkpoint>

## 第 4 步：探索解决方案并收尾（40–55 分钟）

不要问"你想要什么功能？"这是个陷阱。人们要么描述你现有的产品，要么提出他们永远不会用的东西。

应该问行为和结果：

```markdown
## 解决方案与收尾（问题 13–15）

Q13: "如果这个问题明天就消失了，你的日常会有什么不同？"
     → 以结果为导向的思考方式。他们描述的是目标，
       不是功能。

Q14: "你有没有见过谁把这个问题处理得比较好，
     哪怕只是局部解决？他们是怎么做的？"
     → 参照基准。他们可能会提到一个你从没听过的竞品。

Q15: "有没有什么我没问到、但你希望我问的问题？"
     → 永远是最后一道题。永远。你会惊讶于这里冒出来的内容。
```

用下面这段话结束通话：

```
"这次聊天非常有帮助。我后续可能会通过邮件
跟进一两个问题，可以吗？另外，如果你认识
其他有〔这个问题〕的人，非常欢迎介绍给我。
非常感谢！"
```

每一次访谈结束时都要请对方转介绍。招募受访者是用户研究里最难的环节。让你的参与者帮你做这件事。

<Checkpoint>
挂断前确认：你是否已经问了 Q15，并等对方完全说完才道别？
<Answer>是的——Q15 是你问的最后一个问题，你等对方完全说完才结束。这个问题往往会带出整场访谈最重要的洞察。</Answer>
</Checkpoint>

## 第 5 步：输出成果（55–60 分钟）

趁对话还在脑子里鲜活，立刻打开这份模板填写。不要等到明天。

```markdown
## 访谈整理模板

**受访者：** [名字、年龄段、职位]
**日期：** [YYYY-MM-DD]
**时长：** [X 分钟]

---

### 核心金句
[一句原话，最能体现他们最大的痛点或顿悟时刻]

### 痛点（按情绪强度排序）
1. [最强烈——用了很重的措辞或具体数字]
2. [第二个痛点]
3. [第三个痛点]

### 行为与变通方法
- [他们目前用什么代替你的产品]
- [他们自己搭建的任何工具或临时方案]

### 顿悟时刻 / 亮点
[某个他们描述某件事运作良好的时刻——即使不是你的产品]

### 最优先要修的一件事
[如果只能根据这次访谈改一件事，是什么，为什么？]

### 值得留存的引用
- "[原话引用 1]"
- "[原话引用 2]"
- "[原话引用 3]"
```

完成 5 次访谈后，把五份整理文档合并到一个文件里，寻找规律。在 5 次访谈中出现 3 次以上的痛点，就是你的产品路线图。

🎉 你刚刚完成了一次完整的用户访谈——有录音、有脚本、有整理文档，现在就可以发到 Slack 上分享。这比大多数团队一整个季度收集到的用户洞察还要多。

## 🎁 进阶挑战

- **轻量级"日记研究"：** 请受访者在问题下次真实发生时给你发一段语音。你得到的是当下的第一手数据，而不是事后的回忆。
- **用 Otter.ai 自动转录：** 把录音文件上传到 Otter.ai（有免费版），几分钟内得到可搜索的文字稿。搜索"frustrated"或"always"，快速定位最有价值的引用。
- **建立问题库：** 做完 10 次访谈后，你会知道哪 5 个问题对你的产品最有价值。把它们记
